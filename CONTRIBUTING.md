# Contributing

1. Create a focused branch from the repository default branch.
2. Keep changes scoped to the documented behavior and preserve existing licenses.
3. Never commit credentials, personal data, build output, or local environment files.
4. Run the project’s documented checks before opening a pull request.
5. Explain configuration, migration, deployment, and security impact in the PR description.

For user-visible changes, update `README.md` and `CHANGELOG.md`. Report bugs with reproducible steps, expected behavior, and relevant logs with secrets removed.
